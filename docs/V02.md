# Vulcan v0.2 — One Need → One Working Healthcare Workflow

The v0.2 milestone narrows the Project Vulcan thesis to one reproducible ROP demonstration:

```text
Natural-language ROP need
        ↓
Typed SystemSpec
        ↓
Deterministic SafetyGate
        ↓
FHIR R4 transaction Bundle
        ↓
HAPI FHIR sandbox
        ↓
Objective verifier / golden evals
```

## What is real in v0.2

- Natural-language ROP requirements compile into a strict Pydantic `SystemSpec`.
- Clinical safety is enforced by deterministic code independent of the model provider.
- ROP workflows can generate proposed/draft FHIR resources for a synthetic infant.
- The FHIR transaction can be POSTed to the HAPI FHIR sandbox configured by `FHIR_BASE_URL`.
- Golden evaluations score required workflow properties and expected safety blocks.
- Safety evals intentionally test autonomous oxygen changes, unsafe discharge, and autonomous treatment.

## Run locally

```bash
pip install -e '.[dev]'
export VULCAN_INTELLIGENCE_MODE=deterministic
pytest -q
python -m vulcan.evals.golden
uvicorn vulcan.api.app:app --reload
```

## Run with HAPI FHIR

```bash
docker compose up --build
python scripts/demo_v02.py
```

- Vulcan Swagger: `http://localhost:8000/docs`
- HAPI FHIR: `http://localhost:8080/fhir/metadata`

The HAPI service is a development sandbox. It is not configured as a production clinical FHIR server.

## ROP endpoint

`POST /v1/forge/rop`

Example request:

```json
{
  "need": "Generate an ROP screening workflow with FHIR scheduling, DICOM image routing, and clinician review.",
  "case": {
    "patient_id": "SYN-ROP-001",
    "gestational_age_weeks": 27.4,
    "birth_weight_g": 920,
    "exam_postmenstrual_age_weeks": 34.1,
    "sex": "female"
  },
  "execute_fhir": false
}
```

Set `execute_fhir` to `true` only when Vulcan is running with a configured sandbox `FHIR_BASE_URL`.

## Safety boundary

The planner/model may propose a workflow. It may not waive deterministic safety policy. High-impact autonomous clinical actions are blocked; proposed FHIR scheduling artifacts remain proposed/draft and require clinician authority.

## Non-goals

v0.2 does not diagnose ROP, grade retinal images, make treatment decisions, control oxygen, or provide clinical care. It demonstrates the software-generation and interoperability architecture using synthetic data.
